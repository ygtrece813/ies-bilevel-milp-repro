# Reproducibility Package

**Paper:** *Nested exact mixed-integer linear programming for optimal sizing of park-level integrated energy systems*

All results in the paper are generated by the deterministic, seeded pipelines in this package. Every script runs from the package root (all code and data files are intentionally kept **flat**, because the scripts address each other and the data by relative paths).

> **Verification.** This package was smoke-tested from a clean extraction: every fast script runs as documented, and **Experiment 3 (Table 7), Experiment 2 (Table 6), and the merged-front protocol of Section 5.4 reproduce the published CSV/JSON files byte-for-byte (MD5-identical)**. Reviewers: see `REVIEWERS_GUIDE.md` for a step-by-step walkthrough. Figures generated by the scripts are written into `论文图片/`.

## 1. Requirements

- Python >= 3.9
- Packages: `numpy pandas matplotlib scipy scikit-learn xgboost joblib pyomo pulp`
- **CBC solver** executable available on `PATH` (the inner layer is solved with Pyomo + CBC), e.g. `conda install -c conda-forge coincbc`
- Times New Roman (figures are styled by `_paper_figstyle.py`; on systems without the font, matplotlib falls back with a warning)

```bash
pip install numpy pandas matplotlib scipy scikit-learn xgboost joblib pyomo pulp
```

### `published_outputs/`

Pristine copies of exactly the CSV/JSON files behind every figure and table of the paper (fronts, knees, metrics, sensitivity, ablation tables). **Identical working copies sit flat in the package root** (that is where the scripts read and rewrite them), so after a rerun you can byte-compare your outputs against `published_outputs/` with `diff`, `fc`, or MD5 — or re-render all figures directly without running the long experiments.

## 3. How to reproduce

Run all commands from the package root.

| Step | Command | Expected runtime* | Outputs |
|---|---|---|---|
| Exp. 1 main (seed 42) | `python _paper_exp1_compare.py 42` | ~80 min | `_paper_exp1_fronts.csv`, `_paper_exp1_knee.json`, `_paper_exp1_metrics.txt`, Fig. 6 PNG |
| Exp. 1 robustness | `python _paper_exp1_compare.py 43` / `44`, then `python _run_seeds30.py` | ~80 min each + ~17.5 h (batch, 2 workers) | `*_43.csv`, `*_44.csv`, `_paper_exp1_fronts_{45..71}.*` + knees/metrics |
| Merged front + TOPSIS (30 seeds, as in the paper) | `python _merge_fronts30.py` | seconds | `_paper_exp1_fronts_merged30.csv`, `_paper_exp1_knee_merged30.json` |
| Multi-seed aggregation (30 seeds) | `python _seed_agg30.py` | seconds | `_paper_exp1_seeds_agg30.csv` |
| 3-seed merged front (reference) | `python _paper_exp1_merge_fronts.py` | seconds | `_paper_exp1_fronts_merged.csv`, `_paper_exp1_knee_merged.json` |
| Exp. 2 multi-time scale | `python _paper_exp2_multiscale.py` | minutes | `_paper_exp2_table.csv`, Fig. 7 PNG |
| Exp. 3 carbon ablation | `python _paper_exp3_carbon.py` (+ `alice`) | seconds (pure MILP) | `_paper_exp3_table*.csv`, Fig. 8/10 PNG |
| Sec. 5.5 sensitivity | `python _paper_exp1_sens.py` | ~9 x 80 min | `_paper_exp1_sens_T*.csv`, `_paper_exp1_sens_metrics.csv` |
| Second-case pipeline | `python _paper_case2_alice.py` | minutes (XGBoost training) | `ies_forecast_8760_alice*.csv`, `ies_forecast_contract_alice_eui.pkl` |
| Alice two-arm comparison | `python _paper_exp1_compare.py 42 2000 alice` | ~80 min | `*_alice.csv`, `*_alice.json` |

\* on an ordinary desktop PC (CBC solver). `--one` makes `_paper_exp1_sens.py` advance one scenario per process (memory-safe chunking); `_paper_exp1_compare.py` additionally supports chunked generations via its 4th CLI argument (seed, tank bound, case, chunk) with checkpoint resume.

Figure-only re-rendering (no experiments needed):

```bash
python _paper_fig_pareto3d.py          # Fig. 6
python _paper_fig_pareto3d.py alice    # Fig. 9
python _paper_fig2d_replot.py          # Fig. 6 (2D projections)
python _paper_fig1.py                  # Fig. 5
python _paper_exp3_carbon.py --fig-only        # Fig. 8 from existing table
python _paper_exp3_carbon.py alice --fig-only  # Fig. 10
python _paper_draw_diagrams.py         # Figs. 1-4
```

## 4. Raw data (BDG2)

The case data come from the public **Building Data Genome Project 2** dataset (Fox office-building cluster; sites Essie and Alice; see Miller et al., *Building Data Genome Project 2*, Scientific Data 7 (2020) — ref. [28] of the paper). The dataset is distributed under CC BY 4.0 via the official repository (`github.com/buds-lab/building-data-genome-project-2`, mirrored on Kaggle).

The included contracts and 8760-h curves are the processed products of the paper's data pipeline, so **everything in Section 3 runs without the raw dataset**. To regenerate the pipeline from raw meters instead:

1. Download BDG2 and point `DATA_DIR` in `eui_harmonize.py` to the dataset directory (folder containing `metadata.csv`, `weather.csv`, `electricity.csv`, `hotwater.csv`, `chilledwater.csv`, ...).
2. Main case: `python ies_load_forecast_bridge.py <dataset_dir> Fox_office_Essie --export`
3. Second case: `python _paper_case2_alice.py`

## 5. Determinism notes

- All random seeds are fixed: NSGA-II seeds 42 (main) / 43–71 (robustness; 30 seeds in total); Experiment 2 re-seeds the dispatcher noise per typical day (`np.random.seed(42 + day_idx)`); Experiment 3 is a pure MILP solve with no stochastic component (bit-for-bit reproducible).
- Re-running with the same seed on the same platform reproduces the published outputs; across different BLAS/solver builds, last-digit drift in floats is possible.
